Date: 2026-10-07. Reviewer: Astra, high. Decision: **ACCEPT WITH LIMITATIONS** for the reviewed corrections. E4 performance and final visual acceptance remain pending.

Narrow follow-up to Astra/Opus r1: reviewed client freshness, automatic preparation, nonblocking cached-preview handling, final-mip validation, shared coarse integration, startup identity and their regressions. Ran `test_terrain_navigation`, `test_terrain_background`, `test_terrain_final_mips`: **28/28 passed**. Both `node test_terrain_freshness.cjs` and `node test_terrain_lod.cjs` passed. No GPU workload or actual-browser benchmark was run; implementation files were not edited.

## Corrected findings

- **Preview promotion race and flicker resolved.** Progress marks previews for validation while retaining the displayed tile. Each preview expires after two seconds even without background progress, and a response started before the latest coarse revision is admitted as stale. Refresh/pump admit stale resident tiles for replacement. This closes the late-response race and allows foreground-only coverage to become visible. Expiry plus the periodic poll is a retry mechanism, not a two-second end-to-end promotion SLA.
- **Replacement and parent promotion covered.** Disposal of an old resident tile no longer deletes the newly uploaded same-key GPU texture. Non-final LOD 1–2 tiles expire after ten seconds; validation bypasses the browser's long cache lifetime. The Node regression executes the real client functions with controlled responses and checks retained display, late revision, texture survival and parent expiry. It is a unit-level mechanism check, not proof of flicker-free presentation on every renderer/device.
- **Cached previews do not wait for busy GPU work.** `learned_tile_ready()` uses a nonblocking lock attempt and returns the existing preview when the lane is occupied. Its probe only reads already installed foreground/background worlds; it cannot invoke `_available_world()`/`get_world()` and trigger model loading or LRU eviction on this HTTP hit path. The mocked Flask test holds the lock on another thread and receives the cached physical response in less than 250 ms. This validates the lock correction, not a hardware p95 or all-preview latency guarantee. Readiness contributors are deduplicated; when the lock is free, readiness still performs bounded filesystem checks.
- **Shared foreground/background accounting resolved in B2 r3.** Completion, bytes, exhaustion and discovered invalidation share one live namespace ledger under the server's serialized writer model. This removes the whole-plan replay and undercounting defect from integrated preparation.
- **Automatic preparation added.** Opening a world schedules one bounded 8,192-quantum request after its overview is available. Preparation has lower queue priority than visible requests and can be paused; `prepare=0` disables this for isolated benchmarks. This addresses the previous manual-only learned-coverage policy. Code inspection establishes the trigger, not full-world completion time. The server has one global preparation task: another view/start can replace it, and pause is global rather than session-owned. Retain that product limitation in the final documentation.
- **Final-mip cache invalidation now checks usable children.** LOD 1–2 cached decoder parents are invalidated only when `existing_final_mip()` successfully reads and validates all child arrays and identity/stage reports. A corrupt child no longer makes a cached parent regenerate forever merely because filenames exist. The regression uses real CPU child files at LOD 1, including an empty child, rather than the unreachable high-LOD mip case.
- **Remaining supporting corrections check out.** The priority regression now observes `visible, coarse, coarse` without cancelling the background job. Provenance records the Gaussian postfilter and the preview's 7,680 m source grid. New seed manifests reuse the startup source/model/runtime snapshot; the regression rejects attempts to rehash files lazily. The earlier macro disk-index fix remains covered.

No new proven P1/P2 blocker was found in this correction set. An already launched NN quantum remains non-preemptive. Preparation can still fail on queue saturation and need an explicit restart; this does not corrupt persisted windows. Quotas remain per active physical profile/per coarse world, and the dependency memory budget is not a demonstrated hard peak bound.

## Limits on acceptance

The previous real HTTP/browser reports remain historical measurements of their own state. They cannot certify these final edited bytes, automatic preparation behavior, real final-mip promotion, cold visible NN coverage during movement, or whole-world completion. The busy-lock unit test must not be presented as achievement of E4's actual-browser useful-response target. The default request-shape fidelity limitation and failed optional canonical-latent experiment remain as recorded in B2; exact mip means of committed children do not remove them.

Run the final source-bound GPU/HTTP/browser measurements after source freeze, including the planned coverage/preparation evidence. A smooth camera over a procedural preview is not completed cold NN terrain. The benchmark's `prepare=0` run isolates navigation; it cannot establish behavior under the product's default concurrent preparation. The current camera pan helper also remains discrete key steps, not a continuously sampled cold-coverage trace.

**Disposition:** accept the reviewed corrections with these limits. No failed WebGPU NN backend is required for deployment; CUDA remains the production generation path. E4 and human terrain/LOD visual acceptance are not certified by this review.
